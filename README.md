# 龙舟联赛积分与混合组资格

广州龙舟超级联赛赛事后台：记录队伍注册、队员资格、组别规则、赛道船只、分站报名、检录、成绩与积分版本，并对最终晋级给出可追溯解释。

## 领域规则

- **注册与资格**：队伍、队员由秘书处登记；成员关系须秘书处确认资格后才能上场。
- **组别规则**：男子公开组与男女混合组各 20 名划手；混合组女划手不少于 8 人（鼓手、舵手不计入）。
- **报名与检录**：队伍按“分站 × 组别”报名；检录名单通过后冻结，再次提交被拒绝。
- **替补换人**：冻结后只能凭伤病、突发疾病、紧急事务等有效理由申请，秘书处审批时**必须**写明积分是否受影响、晋级是否受影响及依据；替补只把原成员关系标记为“已被替补”，不删除，名单生成新版本。
- **赛道与船只**：临时调整必须填理由与影响说明并留痕；已结算/锁定场次不得调整。
- **成绩接收**：
  - 同一场收到内容一致的成绩 → 幂等返回原结果，不重复入账；
  - 内容不一致 → **只锁定该场积分**并自动立案争议，其他场次/组别照常结算；
  - 秘书处依据录像等主动更正 → 积分台账产生新版本，旧版本作废保留；
  - 成绩确认人与提交人不得为同一人。
- **申诉复核**：申诉期间该场积分冻结；裁决人不得是该场任一成绩版本的提交人（提交人不能独自确认争议）。
- **角色可见范围**：秘书处可见全部；裁判/计时员只见编排、已确认成绩与公开积分；队伍工作人员只见本队；锁定中的积分对队伍不显示分值。
- **晋级**：前四个分站的已确认积分决定年度总决赛分组（示例口径前 4 名进冠军组）；锁定积分不计入确定排名；每队可解释积分来源（场次/名次/版本）、组别资格、换人记录与未决申诉。

## 代码结构

| 路径 | 职责 |
| --- | --- |
| `src/dragon/models.py` | 实体与枚举（队伍、成员关系、检录版本、替补、赛道、成绩版本、台账、申诉、留痕） |
| `src/dragon/rules.py` | 混合组比例、积分表、前四分站口径 |
| `src/dragon/permissions.py` | 四类角色的操作权限与可见范围 |
| `src/dragon/service.py` | 核心写服务：注册、报名、检录冻结、替补、赛道、成绩幂等/锁定/更正、申诉裁决 |
| `src/dragon/qualification.py` | 晋级解释查询与总决赛分组 |
| `src/dragon_context.py` | 原有领域资料（事实/约束）读取与校验 |
| `examples/stage4_demo.py` | 第四站全流程演示（虚构数据） |
| `tests/` | 22 个单元测试 |

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src examples
```

第四站全流程演示：

```bash
python3 -m examples.stage4_demo
```

所有命令只读写仓库内文件，不连接外部业务系统；示例数据均为虚构，不含真实个人信息。
